# The Bell — блоки «Витрина подписок» и «Вебинары» (MVP)

Angular 19, архитектура FSD. **Демо:** _ссылка после деплоя_ · **Код:** этот репозиторий.
Запуск: `cd app && npm ci && npm start`. Оплата в демо — **мок** (тестовая карта `4242 4242 4242 4242`, отказ `4000 0000 0000 0002`).

## Как блоки встраиваются в сетку
Главная собирается из `app/public/cms/layout.json`: список блоков `{id, type, enabled, span}`. Реестр (`pages/home/model/block-registry.ts`) сопоставляет `type` компоненту. Каждый блок сам загружает свой файл `cms/blocks/<id>.json` формы `{settings, content}`; если файл не загрузился, скрывается только этот блок. Новый блок = компонент + строка в реестре + запись в layout.

## Что редакция настраивает в «админке»
Админки нет, её роль играют файлы блоков (`app/public/cms/blocks/<id>.json`, поля в [docs/cms.md](docs/cms.md)). Редакция настраивает **что показать и по какому правилу**, но не оформление: **витрина:** какие продукты участвуют и в каком порядке, с какой даты и как часто меняются, заголовок и три карточки слайда, текст, цена и кнопка широкой карточки; **вебинары:** данные вебинара, его продукт, ссылку на запись, разовое участие, ручной статус, показывать ли прошедшие и сколько всего. Расположение и ширину блоков на странице задаёт существующий конструктор сайта; `layout.json` в демо его заменяет.

## По какой логике блок решает, что показать
- **Витрина:** слайд по дате (`startDate`, `periodDays`, `slideIds`), детерминированно, без случайности. Кнопка ведёт в тарифы продукта.
- **Вебинары:** идущие → ближайшие → прошедшие (свежие первыми); статус считается по дате. Кнопка зависит от доступа: нет доступа → «Подписаться» (+ разовое участие, если оно есть); есть → «Зарегистрироваться», «Подключиться», «Смотреть запись».
- «Сегодня» берётся из серверного времени, если CMS присылает `serverTime`, иначе из часов браузера.
